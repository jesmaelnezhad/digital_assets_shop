## Architecture Overview

Pawradise uses a microservice architecture with 8 backend services. Each service owns its domain and exposes a REST API under `/api/v1/`. All services are stateless and communicate via HTTP.

With domain-based routing (v2, 2026-09-10+), environments are separated by hostname:

```
Client (Browser/App)
    │
    ▼
Host Nginx (port 80/443) ──► ingress-nginx (NodePort 30758)
    │
    ├── staging domain ──────────► staging namespace services
    ├── production domain ───────► production namespace services
    │
    └── Static files ────────────► /var/www/production/assets/
```

### Service Registry

| Service | Port | Database | Responsibility |
|---------|------|----------|----------------|
| Identity | 8081 | identity_db | Users, auth, profiles, referrals |
| Product | 8082 | product_db | Products, categories, tiers, images, bundles |
| Commerce | 8083 | commerce_db | Orders, cart, wishlist, coupons, guest orders |
| Community | 8084 | community_db | Posts, comments, likes, follows |
| Review | 8085 | review_db | Product ratings (verified purchase) |
| Payment | 8086 | payment_db | Payments, exchange rates, crypto calc |
| Admin | 8087 | admin_db | Stats, moderation, settings, email export |
| Media | 8088 | — (PV) | File upload/download, previews |

## Base URLs & Environments

### Domain-Based Routing (v2, 2026-09-10+)

Environments are separated by hostname, NOT path prefix. Both environments use identical `/api/v1` paths.

#### Staging

```
Domain: server-ad5ae8ea-5132-4cd3-b11f-5cb0f43bdc53.eu-west1-a.arvancompute.ir
API:    https://server-ad5ae8ea-5132-4cd3-b11f-5cb0f43bdc53.eu-west1-a.arvancompute.ir/api/v1
```

#### Production (placeholder — real domain TBD)

```
Domain: pawradise.ir (placeholder until real domain provided)
API:    https://pawradise.ir/api/v1
```

### Local Development / Direct Access

```bash
# Access k3s ingress directly (NO host header routing — matches first ingress)
http://130.185.123.156:30758/api/v1/health
```

**Important:** Direct access to the k3s NodePort WITHOUT the proper Host header will match the first ingress (production). Always use the domain name to reach the correct environment.

### Environment Detection (Frontend)

```javascript
// env.js is generated by docker-entrypoint-env.sh using ENV_NAME env var
window.__PAWRADISE_ENV__ = {
  apiBase: "/api/v1",        // Same in both environments
  isStaging: true/false,     // Set by ENV_NAME env var
  envName: "staging"/"production"
};
```

### Admin Token

```bash
# Staging
ADMIN_TOKEN=admin_secret_staging_2026

# Production (set when real domain is configured)
ADMIN_TOKEN=<production-admin-token>
```

## Authentication & Authorization

### JWT Token Flow

1. **Register** → Receive `{ token, user }`
2. **Login** → Receive `{ token, user }`
3. **Subsequent requests** → Header: `Authorization: Bearer <token>`
4. **Logout** → Token revoked server-side (added to blocklist)

### Token Format

- **Type**: JWT (HS256)
- **Claims**: `{ user_id: int, email: string, role: string, exp: int }`
